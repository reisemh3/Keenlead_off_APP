# Cahier des charges — Application mobile & web pour DJ / Beatmaker

## 1. Vision du projet

L’objectif est de créer une application principalement mobile, accompagnée d’une interface web, permettant à une DJ / Beatmaker de centraliser, organiser, écouter et présenter ses créations musicales sans dépendre exclusivement de plateformes comme Spotify.

L’application doit servir à la fois de :

* bibliothèque musicale personnelle ;
* outil pratique pour retrouver et écouter ses sons en situation réelle, notamment en salle, en session DJ ou en déplacement ;
* portfolio professionnel ;
* site vitrine public pour présenter son univers, ses albums, ses sons, son histoire et son identité artistique.

L’expérience doit être simple, rapide, moderne et efficace.

L’univers graphique devra être orienté **PUR Beatmaker** : épuré, musical, urbain, professionnel, premium, sans surcharge visuelle.

---

## 2. Objectifs principaux

### Objectifs fonctionnels

Permettre à l’artiste de :

* ajouter ses morceaux ;
* associer une image d’album ou de cover ;
* renseigner toutes les informations importantes d’un son ;
* créer des albums ou projets musicaux ;
* organiser ses sons par style, ambiance, BPM, tonalité, date, tags ;
* écouter ses sons facilement depuis mobile ;
* préparer des playlists ou sets ;
* rendre certains sons publics ou privés ;
* présenter son univers artistique via une interface web.

### Objectifs professionnels

L’application doit aussi permettre de :

* renforcer son image de marque ;
* partager facilement son portfolio ;
* présenter ses projets musicaux sans dépendre de Spotify ;
* avoir une vitrine propre et maîtrisée ;
* donner une impression sérieuse, artistique et professionnelle.

## 3. Positionnement de l’application

L’application ne doit pas être pensée comme un simple lecteur audio.

Elle doit être pensée comme une **plateforme personnelle d’artiste musical**, entre :

* SoundCloud privé ;
* portfolio musical ;
* bibliothèque audio professionnelle ;
* mini-site officiel ;
* outil de préparation pour DJ set.

* ajouter une cover ;
* créer un album ;
* créer une playlist ;

## 8. Technologies recommandées

### Application mobile

Technologie recommandée :

Flutter avec Dart.

Pourquoi :

* excellente performance mobile ;
* une seule base de code Android / iOS ;
* possibilité de version web ;
* bon rendu visuel ;
* très adapté aux applications modernes ;
* bon choix si l’efficacité mobile est prioritaire.

### Interface web

Deux options possibles.

Option recommandée :

Next.js pour le site vitrine public.

Pourquoi :

* meilleur référencement naturel ;
* meilleur partage des pages sur Google et réseaux sociaux ;
* plus adapté à un portfolio public ;
* plus professionnel pour un site web.

Alternative :

Flutter Web si l’objectif est d’aller plus vite avec une seule technologie.

Recommandation finale :

* Flutter pour mobile ;
* Next.js pour le portfolio web ;
* Supabase pour la base de données ;
* Cloudflare R2 pour le stockage audio.

## 9. Stockage et backend

### Backend recommandé

Supabase.

Utilisation :

* gestion des utilisateurs ;
* authentification ;
* base de données PostgreSQL ;
* gestion des droits ;
* API automatique ;
* stockage des métadonnées ;
* sécurité ;
* espace admin.

### Stockage audio recommandé

Cloudflare R2.

Utilisation :

* fichiers MP3 ;
* fichiers WAV si nécessaire ;
* covers ;
* images d’albums ;
* exports audio ;
* fichiers lourds.

Pourquoi :

* coût faible ;
* adapté aux fichiers lourds ;
* évolutif ;
* pas de dépendance à Spotify ;
* bon choix pour réduire les frais de bande passante.

## 17. Recommandation finale

Le projet doit être construit en deux axes.

Premier axe : l’application mobile, pensée comme l’outil principal de la DJ / Beatmaker.

Deuxième axe : le site web, pensé comme une vitrine professionnelle publique.

Stack recommandé :

* Flutter pour l’application mobile ;
* Next.js pour le site web ;
* Supabase pour le backend ;
* PostgreSQL pour la base de données ;
* Cloudflare R2 pour les fichiers audio et images ;
* Figma pour les maquettes ;
* GitHub pour le code ;
* Vercel ou Cloudflare Pages pour le site web.

La première version doit rester simple, propre et très efficace.

Le but n’est pas de copier Spotify, mais de créer une plateforme personnelle, maîtrisée, élégante et adaptée à l’univers d’une Beatmaker.

L’application doit donner une impression claire :

« Voici mon univers. Voici mes sons. Voici mon identité artistique. Tout est maîtrisé, propre, professionnel et accessible. »
